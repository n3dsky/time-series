# Прогнозирование заказов такси

Прогноз количества заказов такси в аэропорту на следующий час по историческим данным. Учебный проект по временным рядам (Яндекс.Практикум, специальность «Специалист по Data Science»).

## Задача

Компания «Чётенькое такси» собрала исторические данные о заказах в аэропортах. Чтобы привлекать больше водителей в период пиковой нагрузки, нужно прогнозировать число заказов на час вперёд.

Формальное требование: **RMSE на тестовой выборке не выше 48**.

## Данные

`datasets/taxi.csv` - 26 496 записей с 01.03.2018 по 31.08.2018, шаг 10 минут, единственный целевой столбец `num_orders`.

После ресемплирования по одному часу получается 4416 наблюдений без пропусков и разрывов. Среднее число заказов в час - 84, разброс от 0 до 462.

## Результат

| Решение | RMSE (кросс-валидация) | RMSE (тест) |
|---|---|---|
| **Гребневая регрессия (Ridge, alpha=100)** | 22.03 | **34.61** |
| Линейная регрессия | 22.03 | 34.61 |
| LightGBM | 22.30 | 36.81 |
| Бейзлайн: как в тот же час неделю назад | 26.14 | 39.59 |
| Случайный лес | 22.32 | 39.66 |
| Бейзлайн: как в прошлый час | 37.29 | 58.92 |

Итоговая модель проходит порог задачи (34.61 против 48) и, что важнее, обгоняет бейзлайн без машинного обучения на 12.6%. Средняя абсолютная ошибка - 25.5 заказа при среднем уровне 139.6 заказа в час на тестовом периоде.

## Ход работы

**1. Подготовка.** Загрузка с разбором дат в индекс, проверка ряда на монотонность индекса, дубликаты дат, пропуски и равномерность шага. Ресемплирование по часу методом `sum()`.

**2. Анализ.** Ряд разложен на тренд, сезонность и остаток. Построены профили по часам суток и дням недели, тепловая карта «час x день недели», график автокорреляции.

Что нашли:

- **Восходящий тренд**: средние по месяцам растут с 57.5 в марте до 127.7 в августе, то есть в 2.2 раза. Ряд нестационарен, тестовый период лежит выше всех обучающих уровней.
- **Суточная сезонность**: размах средних по часам от 25 заказов в 06:00 до 144 в полночь.
- **Недельная сезонность**: по средним за сутки она кажется слабой (77-91), но это следствие усреднения по всем часам. На тепловой карте «час x день недели» размах по отдельным ячейкам составляет 14-170, то есть сезонности складываются аддитивно.

**3. Признаки.** Набор лагов выведен из автокорреляционной функции, а не подобран перебором. Пики ACF строго кратны суткам, а максимум приходится на лаг 168 часов, то есть ровно неделю (0.72) - выше суточного лага 24 (0.68) и соседнего часа (0.62).

Итоговые признаки: `hour`, `dayofweek`, лаги 1-24, лаги 48, 72, 96, 120, 144, 168, скользящее среднее с окном 12 часов. Все признаки считаются только по прошлым значениям ряда: скользящее среднее берётся с обязательным `shift()` перед `rolling()`, иначе в него попало бы текущее значение и возникла бы утечка целевой переменной.

Признак «месяц» намеренно не добавлялся: в тестовой выборке встречается только август, и модель не смогла бы разумно экстраполировать это значение.

**4. Валидация.** Разделение строго по времени, без перемешивания: тест - последние 10% ряда (441 час, вторая половина августа). Подбор гиперпараметров через `GridSearchCV` на `TimeSeriesSplit` из 5 блоков, где обучение всегда идёт по прошлому, а проверка по следующему за ним отрезку. Тестовая выборка в подборе не участвовала.

**5. Тестирование.** Проверка всех моделей и обоих бейзлайнов, анализ остатков, разбор коэффициентов итоговой модели.

## Выводы

**Признаки решают больше, чем алгоритм.** Разброс между четырьмя моделями на кросс-валидации составил 0.3 RMSE, тогда как правильно выбранный набор лагов улучшил результат на несколько единиц. Автокорреляция дала этот набор сразу, без перебора.

**Простая модель оказалась лучшей.** Зависимость в данных близка к аддитивной (тренд плюс суточная волна плюс недельная поправка), а тестовый период лежит выше обучающего по уровню. Прогноз дерева есть среднее по листу, поэтому оно не может выйти за пределы значений, встреченных при обучении. Линейные модели экстраполируют тренд свободно и потому выигрывают.

**Бейзлайн обязателен.** Случайный лес выглядел приемлемо на кросс-валидации (22.32), но на тесте дал 39.66 и проиграл строчке кода без всякого обучения. Без бейзлайна эта модель сошла бы за рабочую.

**Что можно улучшить.** Модель уверенно повторяет суточную волну и различает дни недели, но срезает самые острые пики: всплески до 400+ заказов не выводятся из прошлых значений ряда. Их объяснили бы внешние данные - расписание рейсов, погода, праздники. Для внедрения стоит также заложить небольшой запас к прогнозу: для задачи «привлечь водителей к пику» недооценка нагрузки неприятнее переоценки.
